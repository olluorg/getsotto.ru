Чем dirty read, non-repeatable read и phantom read отличаются друг от друга?

MiddleТранзакции и изоляцияSQL
Ещё спрашивают так:
  • Что такое грязное чтение?
  • Чем неповторяемое чтение отличается от фантома?
Коротко

Грязное чтение — видим чужие неподтверждённые изменения. Неповторяемое — повторное чтение той же строки даёт другое значение. Фантом — повторный запрос с условием возвращает другой набор строк.

  • Грязное: другая транзакция потом откатится, а мы уже использовали её данные
  • Неповторяемое: между чтениями кто-то закоммитил UPDATE
  • Фантом: между чтениями кто-то закоммитил INSERT или DELETE подходящих строк

А ещё Есть и аномалии вне стандарта: потерянное обновление, асимметрия записи

Уровни изоляции: версии строк, снимки и аномалии

Подробно

Грязное чтение (dirty read). Транзакция A изменила баланс, но не закоммитила. Транзакция B прочитала новое значение и приняла решение. A откатилась — B действовала по данным, которых никогда не было. Запрещено начиная с READ COMMITTED.

Неповторяемое чтение (non-repeatable read). B читает строку, A меняет её и коммитит, B читает ту же строку снова — значение другое. Проблема для транзакций, которые читают данные несколько раз и рассчитывают на их неизменность (отчёт, проверка с последующим действием). Запрещено начиная с REPEATABLE READ.

Фантом (phantom read). B выполняет SELECT ... WHERE status = 'new', A вставляет новую строку с этим статусом и коммитит, B повторяет запрос — строк стало больше. Отличие от неповторяемого чтения: меняется не значение существующей строки, а сам набор. По стандарту запрещено только на SERIALIZABLE (в PostgreSQL снимок скрывает фантомы и на REPEATABLE READ).

Цена изоляции: чем выше уровень, тем больше блокировок или откатов из-за конфликтов сериализации. Поэтому выбирают минимально достаточный уровень и защищают критичные места явно (FOR UPDATE, атомарные UPDATE).
