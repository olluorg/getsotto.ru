Что стоит автоматизировать, а что лучше тестировать вручную?

JuniorАвтоматизацияSeleniumPlaywrightpytest
Ещё спрашивают так:
  • Когда автоматизация тестирования оправдана?
  • Может ли автоматизация полностью заменить ручное тестирование?
Коротко

Автоматизируют повторяющиеся, стабильные и критичные проверки — регресс, smoke, API; вручную — новое, меняющееся и то, где важен человеческий взгляд.

  • Автотест окупается, когда запускается много раз
  • Ручное: исследовательское, юзабилити, разовые и быстро меняющиеся сценарии

А ещё Автоматизация не заменяет ручное тестирование — она освобождает время для него

Так подсказку видит пользователь sotto на живом собеседовании — за пару секунд, пока вы думаете вслух.

Подробно

Автотест — это код, который надо написать и поддерживать. Он выгоден, когда сэкономленное время ручных прогонов больше затрат на разработку и поддержку.

Хорошие кандидаты на автоматизацию:

  • регрессионный набор — запускается на каждой сборке;
  • smoke — быстрый сигнал, что сборка жива;
  • API-тесты — быстрые, стабильные, не зависят от вёрстки;
  • проверки с большим объёмом данных и множеством комбинаций;
  • критичные сценарии — вход, оплата.

Что лучше оставить ручным:

  • новый функционал, который ещё меняется;
  • исследовательское тестирование;
  • юзабилити, внешний вид, впечатление от интерфейса;
  • разовые проверки, которые больше не понадобятся;
  • сложные для автоматизации сценарии: капча, физические устройства.

Уровень автотестов выбирают по пирамиде: больше API и интеграционных, меньше UI. Инструменты для UI — Selenium, Playwright; для API — pytest с requests, REST Assured, Postman/Newman.

Что хотят услышать

  • Критерий окупаемости: частота запусков и стабильность.
  • Конкретные кандидаты на автоматизацию и для ручного тестирования.
  • Автоматизация не заменяет ручное тестирование.
  • Связь с пирамидой тестирования.

Частые ошибки

  • «Нужно автоматизировать всё».
  • Автоматизировать нестабильный функционал, который меняется каждую неделю.
