Чем Integer.valueOf(127) отличается от паттерна Factory Method по GoF?

MiddleПаттерны проектирования
Коротко

Factory Method (GoF) построен на наследовании: базовый класс объявляет метод создания, а какой продукт создать — решает подкласс. Integer.valueOf — статическая фабрика (идиома Effective Java): обычный статический метод вместо конструктора, без иерархии создателей.

  • Статическая фабрика может вернуть кэшированный объект (Integer: −128…127) или подтип
  • Factory Method в JDK: Collection.iterator() — каждая коллекция создаёт свой итератор
  • Путаница терминов частая — интервьюер проверяет именно её

А ещё В Spring «фабричный метод» — ещё и @Bean-метод, создающий бин

Подробно

Factory Method по GoF строится на полиморфизме: базовый класс объявляет метод создания, конкретный класс продукта выбирает подкласс. Integer.valueOf — статическая фабрика из Effective Java: у неё есть имя, она не обязана создавать новый объект (берёт из кэша -128..127) и может вернуть подтип. Пример настоящего Factory Method в JDK — Collection.iterator(): каждая коллекция создаёт свой итератор.

Частые ошибки

  • Называть любой метод со словом factory паттерном Factory Method.
  • Забывать, что статическая фабрика может возвращать кэшированный объект — отсюда ловушка == на Integer.
