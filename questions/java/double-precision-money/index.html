Что выведет System.out.println(0.1 + 0.2 == 0.3) и что брать для денег?

JuniorОсновы языка
Коротко

false: 0.1 непредставимо точно в двоичной плавающей точке (IEEE 754), сумма даёт 0.30000000000000004. Для денег — BigDecimal из строки (new BigDecimal("0.1")) или копейки в long.

  • double сравнивают с допуском: Math.abs(a − b) < eps
  • new BigDecimal(0.1) уже содержит погрешность — BigDecimal.valueOf или строка
  • BigDecimal.equals учитывает масштаб: 2.0 ≠ 2.00, сравнивать compareTo

А ещё Округление — явно: setScale(2, RoundingMode.HALF_EVEN)

Подробно

Дробные числа хранятся в двоичной плавающей точке, где 0.1 непредставимо точно, поэтому сумма даёт 0.30000000000000004. Сравнивать double на равенство нельзя — сравнивают с допуском (|a-b| < eps). Для денег берут BigDecimal и создают его из строки (new BigDecimal("0.1")), а не из double, иначе погрешность переедет внутрь.

Что хотят услышать

  • Причина погрешности.
  • BigDecimal и правильное создание.
  • Сравнение double и BigDecimal.

Частые ошибки

  • Хранить деньги в double/float.
  • Создавать BigDecimal из double-литерала вместо строки.
