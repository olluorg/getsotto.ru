Чего record НЕ делает за вас при проектировании неизменяемого носителя данных?

MiddleООПJava >=16
Коротко

Record делает компоненты private final и генерирует конструктор, аксессоры, equals, hashCode, toString, но не делает защитных копий: изменяемый компонент (List, массив, Date) копируют сами в компактном конструкторе.

  • record Order(List<Item> items) { Order { items = List.copyOf(items); } }
  • Аксессор отдаёт ту же ссылку — копия на входе решает обе стороны, если она неизменяемая
  • Массив в record ломает и equals

А ещё Неизменяемы ссылки, а не объекты за ними

Так подсказку видит пользователь sotto на живом собеседовании — за пару секунд, пока вы думаете вслух.

Подробно

record автоматически делает компоненты private final и генерирует конструктор, геттеры, equals/hashCode и toString. Но он гарантирует неизменяемость только ССЫЛОК: изменяемый компонент (List, массив, Date) всё равно нужно скопировать в компактном конструкторе, иначе через него запись «протекает» и перестаёт быть неизменяемой.
