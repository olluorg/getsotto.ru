Чем this внутри лямбды отличается от this внутри анонимного класса?

MiddleЛямбды и Stream API
Ещё спрашивают так:
  • Чем лямбда отличается от анонимного класса — по семантике и по тому, во что она компилируется?
Коротко

В лямбде this — окружающий объект: она не вводит своей области видимости. В анонимном классе this — сам анонимный объект, и его поля могут перекрывать внешние. Лямбда компилируется не в отдельный .class, а в invokedynamic + LambdaMetafactory; лямбда без захвата переиспользуется как один экземпляр.

  • Лямбда — только для функционального интерфейса; анонимный класс — для любого класса или интерфейса
  • В лямбде нельзя объявить переменную с именем, уже занятым снаружи
  • Анонимный класс всегда держит ссылку на внешний объект — риск утечки

А ещё Лямбда со своим состоянием невозможна — нужен класс

Так подсказку видит пользователь sotto на живом собеседовании — за пару секунд, пока вы думаете вслух.

Подробно

Лямбда — не «короткий анонимный класс»: она не вводит свой scope, поэтому this ссылается на окружающий объект, и транслируется через invokedynamic/LambdaMetafactory (без отдельного .class, без захвата — экземпляр может переиспользоваться). Анонимный класс компилируется в отдельный класс и создаёт новый объект, внутри которого this — он сам.

Что хотят услышать

  • Различие this и области видимости.
  • Способ компиляции.

Частые ошибки

  • Ожидать, что this в лямбде — сама лямбда.
  • Считать лямбду просто синтаксическим сахаром над анонимным классом.
