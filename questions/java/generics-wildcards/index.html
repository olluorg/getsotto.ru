Что такое generics в Java и зачем нужен wildcard ? extends / ? super?

JuniorДженерики
Коротко

Дженерики — проверка типов на компиляции без приведений вручную. Wildcard: ? extends T — из коллекции читают как T (производитель), ? super T — в коллекцию пишут T (потребитель). Правило PECS: Producer Extends, Consumer Super.

  • List<? extends Number> — можно получить Number, нельзя добавить Integer
  • List<? super Integer> — можно добавить Integer, читать только как Object
  • List<?> — только чтение как Object

А ещё Пример из JDK: Collections.copy(List<? super T> dest, List<? extends T> src)

Так подсказку видит пользователь sotto на живом собеседовании — за пару секунд, пока вы думаете вслух.

Подробно

Зачем дженерики:

List names = new ArrayList();          // до Java 5
names.add(42);                         // компилятор молчит
String s = (String) names.get(0);      // ClassCastException в рантайме

List<String> names = new ArrayList<>();
names.add(42);                         // ошибка компиляции

Почему нужны wildcard. Дженерики инвариантны: List<Integer> не подтип List<Number>. Метод sum(List<Number>) не примет список Integer. Решение — sum(List<? extends Number>).

? extends T — за ссылкой может быть List<Integer> или List<Double>. Читать как Number безопасно, а добавить нельзя ничего (кроме null): компилятор не знает, какой именно тип там.

? super T — за ссылкой List<Integer>, List<Number> или List<Object>. Добавить Integer безопасно, а прочитать можно лишь Object.

PECS — источник данных объявляют через extends, приёмник через super:

static <T> void copy(List<? super T> dest, List<? extends T> src)

Частые ошибки

  • Пытаться добавлять элементы в ? extends.
  • Ждать доступности T.class из-за стирания типов.
