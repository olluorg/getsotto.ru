Библиотека объявляет public static final String VERSION = "1.0". В новой версии значение изменили на "2.0" и заменили только jar библиотеки. Что увидит уже скомпилированное приложение?

Старое "1.0": static final примитив или строка с константным инициализатором — константа времени компиляции, её значение вписано прямо в байт-код потребителя. Без перекомпиляции приложения новое значение не подхватится.

  • Ссылки на класс библиотеки в байт-коде вообще не остаётся
  • Обход: инициализировать через метод — VERSION = String.valueOf("2.0") или читать из ресурса
  • Касается и switch по константам

Подробно

Правило такое: static final поле примитивного или строкового типа, инициализированное константным выражением, становится константой времени компиляции, и компилятор подставляет её значение прямо в место использования вместо обращения к полю. Ссылки на класс библиотеки в байткоде не остаётся вовсе, поэтому подмена jar ничего не меняет. Это регулярный источник загадочных расхождений между версиями. Если такое поведение нежелательно, константу лишают статуса компиляционной — например, инициализируют вызовом метода. Из того же правила следует, что обращение к константе не вызывает инициализацию класса: статический блок такого класса не выполнится.

  • Считать, что подмена jar обновит все значения.
  • Забывать, что обращение к константе не инициализирует класс.
