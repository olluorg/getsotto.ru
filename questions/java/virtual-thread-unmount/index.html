Что происходит с виртуальным потоком, когда он выполняет блокирующий сетевой вызов?

MiddleМногопоточностьJava >=21
Коротко

Unmount: стек виртуального потока (continuation) сохраняется в куче, несущий поток освобождается для других задач. Когда данные пришли — mount обратно, возможно на другой несущий поток.

  • Код пишется блокирующим, а стоит как асинхронный
  • Нельзя привязываться к идентичности несущего потока
  • Работает для сетевого ввода-вывода, локов и очередей java.util.concurrent

Подробно

Именно это делает блокирующий стиль снова дешёвым: код пишется прямолинейно, а стоимость ожидания сопоставима с асинхронной моделью. Практические следствия, которые стоит назвать: несущий поток может смениться между операциями, поэтому привязываться к его идентичности нельзя; продолжение сохраняется в куче, значит цена потока — это память под стек, а не под ядро ОС; и планировщик по умолчанию — ForkJoinPool, размер которого задаётся числом ядер. Асинхронного колбэка при этом не возникает: с точки зрения кода вызов остаётся обычным блокирующим.

Частые ошибки

  • Считать, что виртуальные потоки превращают код в асинхронный.
  • Полагаться на то, что несущий поток останется тем же.
