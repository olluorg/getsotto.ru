Вопросы / Java / Код открывает соединение, затем в том же try создаёт из него statement, и оба объявлены в скобках try-with-resources. В каком порядке они закроются?

Код открывает соединение, затем в том же try создаёт из него statement, и оба объявлены в скобках try-with-resources. В каком порядке они закроются?

MiddleИсключения и ресурсы
Коротко

Сначала statement, потом соединение — в обратном порядке объявления, как раскручивается стек: зависимый ресурс закрывается раньше того, из которого получен.

  • Закрыты будут все, даже если close() предыдущего бросил
  • Ресурс, на котором упало создание, закрывать не нужно — его нет
  • Java 9: можно указать уже существующую effectively final переменную

А ещё Обёртки java.io закрывают вложенный поток сами

Так подсказку видит пользователь sotto на живом собеседовании — за пару секунд, пока вы думаете вслух.

Подробно

Порядок не случаен: он гарантирует корректность в типичном случае, когда второй ресурс создан из первого. Закрыть соединение раньше statement означало бы работать с уже закрытым владельцем. Гарантия закрытия при этом полная — каждый объявленный ресурс будет закрыт, даже если close() предыдущего бросил исключение; такие исключения накапливаются как suppressed. Отсюда практический вывод: объявляйте зависимые ресурсы в естественном порядке создания и не пытайтесь закрывать что-либо вручную внутри блока.

Что хотят услышать

  • Порядок и почему.
  • Гарантия закрытия всех.

Частые ошибки

  • Закрывать ресурс вручную внутри try-with-resources — получите двойное закрытие.
  • Объявлять зависимый ресурс раньше того, от которого он зависит.
