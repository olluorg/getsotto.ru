Метод принимает StringBuilder и внутри выполняет sb.append("x"), а затем sb = new StringBuilder(). Что увидит вызывающий код?

MiddleОсновы языка
Ещё спрашивают так:
  • Почему говорят, что Java всегда pass-by-value, если изменения объекта внутри метода видны снаружи?
Коротко

Вызывающий увидит добавленный символ, но не новый объект: Java всегда передаёт по значению, а для ссылочных типов значение — копия ссылки. Мутация объекта по копии видна всем, переприсваивание копии — нет.

  • «Объекты передаются по ссылке» — неточная формулировка
  • Swap двух объектов через метод в Java невозможен
  • Неизменяемые объекты (String, Integer) защищены от изменений внутри метода

Подробно

Формулировка «объекты передаются по ссылке» — самая живучая путаница в теме. На самом деле по значению передаётся всё, просто для ссылочных типов значением является сама ссылка. Копия ссылки указывает на тот же объект, поэтому вызовы, меняющие его состояние, видны снаружи. Присваивание же переставляет только локальную копию, и на переменную вызывающего это не влияет. Отсюда следствие: «вернуть значение через параметр» в Java невозможно — нужен возврат результата или объект-контейнер. Модификатор final у параметра запрещает переприсваивание внутри метода, но на семантику передачи не влияет.

Что хотят услышать

  • Pass-by-value для ссылок.

Частые ошибки

  • Говорить, что объекты в Java передаются по ссылке.
  • Ожидать, что переприсваивание параметра изменит переменную вызывающего.
