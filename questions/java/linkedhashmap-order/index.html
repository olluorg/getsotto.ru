Какое свойство LinkedHashMap отличает его от HashMap?

MiddleКоллекции
Ещё спрашивают так:
  • Как сохранить порядок ключей в Map?
Коротко

LinkedHashMap — HashMap плюс двусвязный список записей: обход в порядке вставки (по умолчанию) или в порядке доступа (accessOrder = true).

  • HashMap порядок обхода не гарантирует
  • Режим доступа + removeEldestEntry = LRU-кэш
  • Сложность get/put та же, O(1)

А ещё Повторный put существующего ключа порядок вставки не меняет

Так подсказку видит пользователь sotto на живом собеседовании — за пару секунд, пока вы думаете вслух.

Попробуйте сами

LRU-кэш: хеш-таблица плюс двусвязный список

Подробно

HashMap раскладывает записи по корзинам хеш-таблицы; обход идёт по корзинам, поэтому порядок зависит от хешей и меняется при расширении.

LinkedHashMap наследует HashMap и связывает все записи двусвязным списком. Режимы:

  • порядок вставки (по умолчанию) — обход в порядке первого добавления ключа; повторный put того же ключа порядок не меняет;
  • порядок доступа (new LinkedHashMap<>(16, 0.75f, true)) — каждый get, put, getOrDefault переносит запись в конец.

Метод removeEldestEntry(Map.Entry eldest) вызывается после вставки; если вернуть true, самая старая запись удаляется — так получается LRU-кэш в несколько строк.

Цена: две дополнительные ссылки на запись и поддержка списка при изменениях. Зато обход пропорционален числу элементов, а не ёмкости таблицы.

Типичные применения: JSON с сохранённым порядком полей, кэш LRU, реестры, где важен порядок регистрации.

Что хотят услышать

  • Двусвязный список поверх хеш-таблицы.
  • Два режима порядка.
  • LRU через accessOrder и removeEldestEntry.

Частые ошибки

  • Думать, что повторный put перемещает ключ в конец в режиме вставки.
