Что делает конструкция try-with-resources?

JuniorИсключения и ресурсыJava >=7
Ещё спрашивают так:
  • Что такое AutoCloseable?
  • Что такое подавленные исключения (suppressed)?
  • Чем try-with-resources лучше finally?
  • Что требуется от ресурса, чтобы работать в try-with-resources?
Коротко

try-with-resources гарантированно закрывает ресурсы при любом выходе из блока — без ручного finally.

  • Ресурс должен реализовывать AutoCloseable; закрываются в обратном порядке объявления
  • Ошибка при закрытии не затирает основное исключение — сохраняется как suppressed

А ещё Перехват исключений — отдельно: catch пишут как обычно

Так подсказку видит пользователь sotto на живом собеседовании — за пару секунд, пока вы думаете вслух.

Подробно

Ресурсы — файлы, соединения с базой, сокеты — нужно закрывать, иначе они утекают. Раньше это делали в finally с проверкой на null и вложенным try, и код получался громоздким и с ошибками.

Конструкция try (Resource r = ...) { ... } закрывает объявленные ресурсы автоматически при любом выходе: обычном, через return или исключение. Требование одно — ресурс реализует AutoCloseable (или Closeable). Если ресурсов несколько, они закрываются в обратном порядке объявления.

Решена и вторая проблема ручного подхода. Если в блоке возникло исключение, а потом упало ещё и close(), в старом коде исключение из finally затирало исходное — терялась настоящая причина. В try-with-resources основным остаётся исключение из блока, а ошибка закрытия прикрепляется к нему как подавленное (getSuppressed()).

С Java 9 можно указывать уже объявленную effectively final переменную: try (conn) { ... }.

Пример

try (var conn = dataSource.getConnection();
     var stmt = conn.prepareStatement("SELECT name FROM users WHERE id = ?")) {
    stmt.setLong(1, id);
    try (var rs = stmt.executeQuery()) {
        return rs.next() ? rs.getString(1) : null;
    }
} // rs, stmt и conn закрыты, даже если было исключение

Что хотят услышать

  • Автоматическое закрытие при любом выходе из блока.
  • Требование AutoCloseable и порядок закрытия.
  • Подавленные исключения вместо затирания основного.

Частые ошибки

  • Закрывать ресурс вручную внутри блока и получать двойное закрытие.
  • Считать, что конструкция сама обрабатывает исключения.
