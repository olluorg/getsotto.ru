Что такое binder в Spring Cloud Stream?

SeniorSpring Cloud StreamSpring Cloud
Ещё спрашивают так:
  • Как Spring Cloud Stream подключается к Kafka или RabbitMQ?
Коротко

Binder — адаптер Spring Cloud Stream к конкретному брокеру (Kafka, RabbitMQ, Pulsar, облачные очереди). Код работает с функциями и «привязками» (bindings), а binder связывает их с топиками или exchange по конфигурации.

  • Смена брокера — смена зависимости binder'а и настроек
  • Bindings: handle-in-0 → destination (топик), group (группа потребителей)
  • Специфичные настройки брокера — в spring.cloud.stream.kafka.* или .rabbit.*

А ещё Абстракция не прячет различия гарантий и модели брокеров

Так подсказку видит пользователь sotto на живом собеседовании — за пару секунд, пока вы думаете вслух.

Подробно

Модель Spring Cloud Stream: приложение объявляет функции (Supplier, Function, Consumer), фреймворк создаёт для них привязки — входные имя-in-0 и выходные имя-out-0. Конфигурация связывает привязки с местом назначения:

spring.cloud.stream.bindings:
  handleOrder-in-0:
    destination: orders
    group: billing
  handleOrder-out-0:
    destination: invoices

Binder — реализация для конкретного брокера: spring-cloud-stream-binder-kafka, -rabbit, Kafka Streams binder, Pulsar, облачные. Он создаёт потребителей и продюсеров, топики или очереди, конвертирует сообщения.

Плюсы: единый стиль кода для разных брокеров, меньше шаблонного кода, конвертация, повторы и DLQ настройками.

Ограничения: гарантии, порядок, повторы и модель групп у Kafka и RabbitMQ разные; тонкая настройка всё равно специфична для брокера. «Смена брокера одной строкой» на практике редко бывает бесплатной.
