Одно и то же свойство задано в application.yml, в переменной окружения и аргументом командной строки. Какое значение победит?

  • Какой источник настроек Spring Boot сильнее?
Коротко

Победит аргумент командной строки. Порядок (сильнее → слабее): командная строка → системные свойства JVM → переменные окружения → профильные файлы → application.yml → значения по умолчанию.

  • Файлы снаружи jar сильнее файлов внутри
  • Профильный файл сильнее общего
  • Итог и источник каждого значения — /actuator/env

Подробно

Spring Boot собирает свойства из упорядоченного набора источников, и более внешний источник перекрывает более внутренний — логика в том, чтобы конфигурацию можно было переопределить при развёртывании, не пересобирая артефакт. Внутри файлов действует своя иерархия: файлы вне jar важнее упакованных, а профильные важнее общих. Полезно знать про relaxed binding: переменная окружения SPRING_DATASOURCE_URL соответствует свойству spring.datasource.url, потому что подчёркивания и регистр приводятся к общему виду. Проверить фактический источник значения можно эндпоинтом Actuator /actuator/env, что здорово экономит время при разборе неожиданной конфигурации.

Что хотят услышать

Частые ошибки

  • Держать секреты в application.yml вместо внешних источников.
  • Забывать про профильные файлы при отладке «неправильного» значения.
