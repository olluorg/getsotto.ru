Какой scope у Spring-бина по умолчанию?

JuniorБины и их жизненный циклSpring
Ещё спрашивают так:
  • Какие бывают scope бинов?
Коротко

По умолчанию singleton — один экземпляр на контейнер, общий для всех потоков. Ещё: prototype (новый на каждый запрос к контейнеру), веб-scope request, session, application, websocket.

  • Singleton должен быть потокобезопасным — без изменяемого состояния
  • Prototype в singleton внедряется один раз — нужен ObjectProvider или lookup
  • Для prototype контейнер не вызывает @PreDestroy

А ещё Singleton Spring — один на контекст, а не на JVM, как паттерн Singleton

Так подсказку видит пользователь sotto на живом собеседовании — за пару секунд, пока вы думаете вслух.

Подробно

singleton (по умолчанию) — контейнер создаёт один экземпляр при старте (или при первом обращении, если @Lazy) и отдаёт его всем. Все запросы обслуживаются одним объектом в разных потоках — поэтому сервисы должны быть без изменяемого состояния: поле currentUser в контроллере — гонка между запросами.

prototype — каждый getBean() или внедрение создаёт новый объект. Контейнер не управляет его уничтожением.

Веб-scope (в веб-контексте):

  • request — на HTTP-запрос;
  • session — на HTTP-сессию;
  • application — на ServletContext;
  • websocket — на WebSocket-сессию.

Такие бины внедряются в singleton через scoped proxy: в singleton лежит прокси, который при каждом вызове находит экземпляр текущего запроса.

Ловушка prototype в singleton: singleton создаётся один раз, и prototype-зависимость внедрится тоже один раз. Для нового экземпляра при каждом использовании — ObjectProvider<T>.getObject(), @Lookup-метод или scoped proxy.

Частые ошибки

  • Хранить состояние запроса в поле singleton-бина.
  • Ожидать новый prototype при каждом вызове метода singleton.
