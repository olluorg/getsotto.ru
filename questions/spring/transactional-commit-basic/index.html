Что происходит при выходе из метода с @Transactional, если исключений не было?

Junior@TransactionalSpring
Ещё спрашивают так:
  • Когда @Transactional коммитит?
Коротко

Успешный выход из метода — коммит (если метод начал транзакцию). Исключение по умолчанию откатывает только неконтролируемые (RuntimeException, Error); checked — коммит.

  • Если транзакцию начал внешний метод, коммит произойдёт при выходе из него
  • rollbackFor — откат и на checked
  • Работает только при вызове через прокси

А ещё Перед коммитом Hibernate делает flush изменений

Так подсказку видит пользователь sotto на живом собеседовании — за пару секунд, пока вы думаете вслух.

Подробно

Границей транзакции служит вызов метода: прокси открывает её перед входом и завершает после выхода. Важная деталь умолчания, которую любят спрашивать: откат происходит при RuntimeException и Error, а вот проверяемое исключение транзакцию не откатывает — если это нужно, поведение задают параметром rollbackFor. Вторая деталь: перехват работает только для внешних вызовов, поэтому обращение к методу изнутри того же класса транзакцию не откроет вовсе.

Что хотят услышать

  • Коммит при успешном выходе.
  • Правило отката.

Частые ошибки

  • Ожидать отката при проверяемом исключении.
  • Ловить исключение внутри транзакционного метода и тем самым отменять откат.
