Что даёт объявление интерфейса, наследующего JpaRepository?

JuniorSpring Data JPA и HibernateSpring Data
Ещё спрашивают так:
  • Зачем наследовать JpaRepository?
Коротко

Реализацию генерирует Spring Data: CRUD (save, findById, delete), пагинация и сортировка, и запросы, выведенные из имён методов (findByEmail).

  • Свой запрос — @Query
  • Не нужно писать DAO-класс
  • Под капотом — EntityManager и Hibernate

А ещё Опечатка в имени метода видна при старте

Так подсказку видит пользователь sotto на живом собеседовании — за пару секунд, пока вы думаете вслух.

Подробно

Имя метода разбирается по правилам, и findByEmailAndStatus превращается в соответствующий запрос без единой строки кода. Когда правил не хватает, запрос задают явно через @Query. Полезно знать границу удобства: чем сложнее условие, тем длиннее и хуже читается имя метода — начиная с некоторого момента честнее написать запрос явно. Схему таблиц Spring Data не создаёт: этим занимается генерация схемы Hibernate или, что правильнее для боевых систем, инструмент миграций.

Что хотят услышать

  • Что генерируется.
  • Запросы по имени метода и @Query.

Частые ошибки

  • Строить метод с именем из десятка условий вместо явного запроса.
  • Полагаться на автоматическую генерацию схемы в production.
