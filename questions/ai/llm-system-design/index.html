Спроектируйте ассистента поддержки интернет-магазина на LLM.

SeniorLLM в продакшене
Ещё спрашивают так:
  • Как бы вы спроектировали чат-бота на LLM для поддержки клиентов?
  • Системный дизайн RAG-ассистента
Коротко

Начать с требований: какие вопросы закрывает бот (статус заказа, возврат, доставка), объём (например, 20 тысяч диалогов в день), допустимая задержка, доля передачи оператору, бюджет, где можно обрабатывать данные. Архитектура: API с авторизацией → оркестратор → маршрутизация по типу вопроса → RAG по базе знаний и инструменты (заказы, доставка, возвраты с подтверждением) → guardrails → потоковый ответ; передача оператору с резюме диалога. Вокруг — оценка качества, трассировка, учёт стоимости.

  • Простые частые вопросы — дешёвая модель или шаблоны, сложные — сильная модель
  • Действия с деньгами — только через инструменты с проверкой прав и подтверждением
  • Метрики: доля решённых без оператора, CSAT, стоимость на обращение, доля ошибок

А ещё Запуск поэтапно: подсказки оператору → ответы на часть тем → расширение по метрикам

Так подсказку видит пользователь sotto на живом собеседовании — за пару секунд, пока вы думаете вслух.

Подробно

Оценка нагрузки (пример): 20 тысяч диалогов в день, 6 сообщений в диалоге, пик в 3 раза выше среднего → около 4 запросов к модели в секунду в пик. При 3 тысячах входных и 300 выходных токенов на запрос — около 400 млн токенов в месяц: это определяет выбор модели и лимиты провайдера.

Компоненты:

компонентрешение
входавторизация клиента, лимиты, guardrails (персональные данные, токсичность, инъекции)
маршрутизацияклассификатор темы: справка, заказ, жалоба, оператор
знанияRAG: гибридный поиск по базе знаний и правилам, реранкер, ссылки
действияинструменты к API заказов и доставки с правами текущего клиента
моделишлюз: основная и резервная модель, кэш префикса, учёт затрат
выходпроверка ответа, запрет обещаний вне правил, потоковая выдача
операторпередача с резюме диалога и найденными данными
данныедиалоги, трассы, оценки, логи — с маскированием персональных данных

Качество: набор из реальных обращений по темам, автоматическая оценка при каждом изменении, ежедневный разбор выборки диалогов, онлайн-метрики и A/B-тест при запуске.

Отказоустойчивость: таймауты и резервная модель; при недоступности модели — сразу оператор; инструменты с идемпотентными операциями.

Риски: обещания вне правил (компенсации), утечки чужих заказов, инъекции через текст обращения, галлюцинации в правилах возврата.

Что хотят услышать

  • Требования и оценка нагрузки до архитектуры.
  • RAG и инструменты с правами пользователя, передача оператору.
  • Оценка качества, наблюдаемость, стоимость, поэтапный запуск.
