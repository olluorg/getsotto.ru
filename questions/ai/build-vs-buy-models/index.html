Когда переходить с внешнего API моделей на собственные модели?

SeniorLLM в продакшене
Ещё спрашивают так:
  • Свои открытые модели или API провайдера — как выбрать?
Коротко

Решение принимают по четырём осям: данные (можно ли отправлять наружу — 152-ФЗ, коммерческая тайна), стоимость при реальной нагрузке, качество на своих задачах и команда (кто будет эксплуатировать GPU-инфраструктуру). Свои модели выгодны при большом стабильном объёме, узких задачах, где дообученная маленькая модель догоняет большую, и жёстких требованиях к данным. При малом и неровном трафике API дешевле: вы не платите за простой GPU.

  • Посчитать полную стоимость: GPU, резерв, инженеры, мониторинг, обновления
  • Гибрид: сложное — во внешнюю сильную модель, массовое — в свою маленькую
  • Решение проверять пилотом на своём наборе оценки, а не по бенчмаркам

А ещё Сильнейшие модели закрыты; своя модель почти всегда уступает лучшим по общим задачам

Так подсказку видит пользователь sotto на живом собеседовании — за пару секунд, пока вы думаете вслух.

Подробно

Пример расчёта. Сервер с одной GPU класса 80 ГБ стоит условно 150–300 тысяч рублей в месяц в аренде. Если он обрабатывает поток, который через API обошёлся бы дороже, и загружен круглосуточно — выгодно. Если загрузка 10% — вы платите за простой. Плюс резерв на отказ, плюс время инженеров.

Факторы за свои модели:

  • требования к данным и контуру;
  • стабильная большая нагрузка;
  • узкая задача (классификация, извлечение), где дообученная модель на 7–14 млрд параметров достаточно хороша;
  • независимость от изменений и цен провайдера.

Факторы против:

  • качество на сложных задачах;
  • нужна экспертиза в serving (vLLM), квантизации, мониторинге GPU;
  • собственные обновления моделей и безопасность.

Путь: начать с API, накопить данные и набор оценки, затем перенести массовые узкие задачи на свою модель и сравнить на наборе.

Что хотят услышать

  • Оси решения: данные, стоимость, качество, команда.
  • Расчёт полной стоимости и загрузки.
  • Гибридный подход и проверка пилотом.
