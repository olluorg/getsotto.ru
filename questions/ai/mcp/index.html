Что такое Model Context Protocol (MCP)?

MiddleИнструменты и агенты
Ещё спрашивают так:
  • Чем MCP отличается от обычного tool calling?
Коротко

MCP — открытый протокол, стандартизирующий подключение инструментов и данных к LLM-приложениям. MCP-сервер публикует инструменты (tools), ресурсы (данные) и шаблоны промптов; клиент (ассистент, IDE, агент) подключается к любому совместимому серверу без отдельной интеграции. Tool calling — механизм модели вызывать функции; MCP — стандарт того, откуда эти функции берутся.

  • Решает проблему «N приложений × M интеграций»
  • Транспорты: stdio для локальных серверов, HTTP для удалённых
  • Безопасность — главный вопрос: сервер получает доступ к данным и действиям

А ещё Удалённые серверы используют OAuth для авторизации пользователя

Так подсказку видит пользователь sotto на живом собеседовании — за пару секунд, пока вы думаете вслух.

Подробно

Проблема. Каждое LLM-приложение раньше писало свои интеграции с GitHub, базой данных, CRM, файловой системой. MCP — общий протокол, как USB для инструментов: интеграцию пишут один раз в виде сервера, и она работает во всех клиентах.

Примитивы:

  • tools — действия, которые модель может вызвать (с JSON-схемой параметров);
  • resources — данные, которые приложение может подставить в контекст;
  • prompts — готовые шаблоны сценариев.

Протокол построен на JSON-RPC; клиент запрашивает у сервера список возможностей и вызывает их.

Риски и практики:

  • сервер видит данные и выполняет действия от имени пользователя — ставить только доверенные серверы, давать минимальные права;
  • описания инструментов попадают в промпт — вредоносный сервер может внедрить инструкции (tool poisoning);
  • подтверждение пользователем опасных действий;
  • для удалённых серверов — авторизация (OAuth) и аудит.

Что хотят услышать

  • Назначение протокола и архитектура клиент-сервер.
  • Различие с tool calling.
  • Риски безопасности.
