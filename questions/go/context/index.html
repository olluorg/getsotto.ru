Зачем нужен context.Context?

JuniorГорутины и каналы
Ещё спрашивают так:
  • Как в Go отменить запрос и передать таймаут вниз по вызовам?
Коротко

Context переносит отмену, дедлайн и значения запроса через цепочку вызовов и горутин. Создают от входящего запроса, передают первым аргументом во все функции с вводом-выводом. WithTimeout/WithCancel порождают дочерний контекст; отмена родителя отменяет всех потомков.

  • Обязательно вызывать cancel() (через defer) — иначе утечка таймера
  • ctx.Done() — канал, закрывающийся при отмене; ctx.Err() — причина
  • Значения (WithValue) — только для данных запроса: trace id, пользователь

А ещё Не хранить context в структурах — передавать явно

Так подсказку видит пользователь sotto на живом собеседовании — за пару секунд, пока вы думаете вслух.

Подробно

Проблема. Клиент отключился или истёк таймаут — а сервис продолжает ходить в базу и другие сервисы, тратя ресурсы. Context даёт единый способ сообщить всем участникам: «работа больше не нужна».

Дерево контекстов. context.Background() — корень; HTTP-сервер даёт r.Context(), который отменяется при разрыве соединения. Производные контексты добавляют таймаут или отмену; дедлайн потомка не может быть позже родительского.

Поддержка в библиотеках: http.NewRequestWithContext, db.QueryContext, клиенты gRPC, Redis, Kafka принимают контекст и прерывают операцию.

Свои долгие функции проверяют ctx.Err() или слушают ctx.Done() в select.

WithValue — не замена параметрам: только сквозные данные запроса, ключ — неэкспортируемый тип, чтобы не было коллизий.

Пример

func handler(w http.ResponseWriter, r *http.Request) {
    ctx, cancel := context.WithTimeout(r.Context(), 2*time.Second)
    defer cancel()

    user, err := repo.Get(ctx, id)        // драйвер БД прервёт запрос при отмене
    if errors.Is(err, context.DeadlineExceeded) {
        http.Error(w, "timeout", 504); return
    }
}

Что хотят услышать

  • Отмена и дедлайны через дерево контекстов.
  • Передача первым аргументом и cancel.
  • Ограничения WithValue.
