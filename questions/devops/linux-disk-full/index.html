Диск заполнен, а du показывает, что места занято мало. В чём дело?

MiddleLinux и диагностика
Ещё спрашивают так:
  • Как найти, что занимает место на диске?
  • Что такое inodes?
Коротко

Частая причина — удалённый файл, который ещё держит открытым процесс (например, лог после ротации): имя исчезло, du его не видит, а место не освободилось. Найти: lsof +L1 или lsof | grep deleted; освободить — перезапуск процесса или усечение через /proc. Вторая причина — закончились inodes при множестве мелких файлов: df -i.

  • df — место на файловой системе, du — сумма размеров видимых файлов
  • Поиск больших каталогов: du -xh --max-depth=1 / | sort -h
  • Docker: старые образы и логи контейнеров — docker system df

А ещё Ротацию логов настраивают с перезапуском или copytruncate, иначе проблема повторится

Так подсказку видит пользователь sotto на живом собеседовании — за пару секунд, пока вы думаете вслух.

Подробно

Диагностика по шагам:

df -h                      # какая ФС заполнена
df -i                      # не кончились ли inodes
du -xh --max-depth=1 / 2>/dev/null | sort -h   # крупные каталоги
lsof +L1                   # удалённые, но открытые файлы

Удалённый открытый файл. В Linux файл существует, пока есть хотя бы одна ссылка: имя в каталоге или открытый дескриптор. rm удаляет имя, а процесс продолжает писать в файл. Решение — заставить процесс переоткрыть файл (сигнал, перезапуск) или : > /proc/PID/fd/N для усечения.

Inodes — структуры описания файлов; их число задаётся при создании ФС. Миллионы мелких файлов (кэш, сессии) исчерпывают inodes при свободном месте — «No space left on device» при df -h 60%.

Профилактика: ротация и лимиты логов (logrotate, лимиты Docker log-driver), алерт на заполнение диска и inodes, очистка образов.
