HTTP и HTTPS

Основа с Junior

Протокол обмена между клиентом и сервером — методы, коды ответа, заголовки, кэширование, версии протокола и шифрование.

HTTP — текстовый протокол «запрос — ответ». Запрос состоит из метода, пути, заголовков и тела; ответ — из кода состояния, заголовков и тела. HTTPS — тот же HTTP внутри зашифрованного TLS-соединения.

GET /api/orders/42 HTTP/1.1
Host: shop.example.com
Accept: application/json
Authorization: Bearer eyJhbGciOi...

HTTP/1.1 200 OK
Content-Type: application/json
Cache-Control: private, max-age=60

{"id": 42, "status": "paid"}

Что важно знать

  • Методы: GET (чтение, без тела, безопасный), POST (создание, действие), PUT (замена), PATCH (частичное изменение), DELETE. Идемпотентность: GET, PUT, DELETE можно безопасно повторить, POST — нет.
  • Коды: 2xx — успех, 3xx — перенаправление, 4xx — ошибка клиента (400, 401, 403, 404, 409, 429), 5xx — ошибка сервера (500, 502, 503, 504).
  • Заголовки: Content-Type, Authorization, Cookie и Set-Cookie, Cache-Control, ETag, CORS-заголовки.
  • Кэширование: Cache-Control: max-age, no-cache (проверять каждый раз) против no-store (не хранить), условные запросы с ETag и ответ 304.
  • Версии: HTTP/1.1 — одно соединение на запрос в момент времени, HTTP/2 — мультиплексирование в одном соединении, HTTP/3 — QUIC поверх UDP без блокировки всей очереди при потере пакета.
  • HTTPS: шифрование, целостность и проверка подлинности сервера по сертификату.

401 и 403 путают чаще всего: 401 — «вы не представились», 403 — «представились, но нельзя».

Критерии освоения

Junior ≈ 6 ч

  • Называет методы и коды ответа HTTP и выбирает подходящие для своего API
  • Читает запрос и ответ в curl и DevTools — заголовки, тело, коды
  • Объясняет разницу 401 и 403, 502 и 504

Практика. Описать API ассистента (5 эндпоинтов) с методами, кодами ошибок и примерами запросов в curl.

Middle ≈ 4 ч

  • Настраивает кэширование ответов заголовками Cache-Control и ETag
  • Объясняет, что дают HTTP/2 и потоковая передача для ответов LLM

Практика. Включить потоковую выдачу ответа через SSE за nginx и проверить, что ответ не буферизуется.

Вопросы с собеседований

  • Какие HTTP-методы вы знаете? Чем GET отличается от POST? Junior

    GET — получить данные, POST — создать или отправить, PUT — заменить целиком, PATCH — изменить частично, DELETE — удалить.

  • Какие коды ответа HTTP вы знаете? Junior

    Пять групп: 1xx информационные, 2xx успех, 3xx перенаправление, 4xx ошибка клиента, 5xx ошибка сервера.

  • Чем отличаются HTTP/1.1, HTTP/2 и HTTP/3? Middle

    HTTP/1.1 — текст, один запрос за раз в соединении. HTTP/2 — бинарные кадры, много потоков в одном TCP-соединении. HTTP/3 — то же поверх QUIC (UDP), без общей блокировки при потере…

  • Как работает HTTPS и TLS-рукопожатие? Middle

    TLS даёт шифрование, целостность и подлинность сервера. В рукопожатии стороны согласуют общий ключ (обмен Диффи — Хеллмана), сервер доказывает владение сертификатом, дальше данные…

  • Что означает буква R в аббревиатуре REST применительно к проектированию API? Junior

    REST — Representational State Transfer: ресурсы адресуются URL, действия выражаются методами HTTP, клиент работает с представлениями ресурсов.
